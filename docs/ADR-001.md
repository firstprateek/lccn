# ADR-001: Local Storage Model (IndexedDB v1)

## Context
- Local-first MVP; must work offline; fast edits; minimal deps; debuggable.

## Decision
- **IDs**: ULID strings (lexicographically sortable; collision-safe).
- **Ordering**: cells start at 100; insert = last + 100.
- **Schema v1**:
  - `notebooks` (keyPath: "id")
  - `cells` (keyPath: ["notebookId","id"], index "byNotebook" on "notebookId")
  - `snapshots` (keyPath: ["notebookId","createdAt"], index "byNotebook")
  - `meta` (keyPath: "key")
- **Access patterns**: `listCells(byNotebook)` dominates; writes small & frequent; snapshots append-only.
- **Consistency**: local read-your-writes; eventual cross-device (future sync).
- **Migration**: Version 1 now; future upgrades in `onupgradeneeded` with backfills.

## Consequences
- **Pros**: offline works; transparent schema; small surface area.
- **Cons**: IDB is verbose; will need compaction/reorder tools later.
- **Risks**: browser quota; very large docs may need paging/virtualization.

## Alternatives
- **Dexie/localForage**: simpler APIs, but hides upgrades/transactions—less control for learning.
